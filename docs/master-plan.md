# Historical master plan for the ModernUO conversion

This is the original design brief for the compiler experiment preserved at `archive/forge-conversion`. The active Ultima Offline 7 design and milestones are in the [roadmap](roadmap.md).

You are the lead engineer for **Ultima Offline**. Build a Windows-first toolchain that takes the player’s own installations of **Ultima VII: The Black Gate** and the **Ultima Online Classic** client data, then generates a playable, single-player campaign on **ModernUO**, viewed through **ClassicUO**.

The first complete release is **English DOS Black Gate without Forge of Virtue**. Forge of Virtue comes later as a separately qualified edition. Serpent Isle is out of scope. **When UO mechanics would change the outcome of an original quest, preserve the Ultima VII outcome.** Use UO artwork, controls, movement, combat and interface conventions wherever they satisfy that rule.

Build the original Black Gate world on a private UO facet. Do not place its quests into stock UO Britannia or reconstruct towns from screenshots. The player should recognize UO on sight and be able to solve Black Gate by knowing Black Gate.

**The central engineering requirement is to preserve what the game can observe.** A chest can look different. But if a script searches for the chest, inspects its quality, removes a particular item, sets a flag and later asks whether that same item is in the Avatar’s possession, every step must still work. A visually perfect chest baked into the map would fail that requirement.

## 1. Start from the evidence already available

The recreation in the project brief is **Anthony Salter’s Ultima VII: Revisited**. Use it. Its author reports that the Trinsic demo implements the town’s storyline, shops, inventory, audio and movement across elevations. That makes Trinsic an unusually good first comparison: there are an original game, a mature reimplementation, and a second recreation to inspect. The author also explicitly describes Revisited as changing aspects of the original experience, so it cannot decide a disputed Black Gate behavior by itself. [Revisited project and demo](https://www.u7revisited.com/)

The answer to “does the Usecode-to-Lua converter already exist?” is precise: **the author says he has a conversion system; the conversion occurred; a reusable public command that reproduces it from an arbitrary installation was not identified in the inspected repository.** The April 2025 commit reports converting 1,012 functions. The inspected November 2026 tree contains 1,078 Lua files in `Redist/Data/Scripts/`, including helpers. The project’s older inventory reports 1,026 scripts and approximately 4,573 calls named `unknown_XXXXH`. Those are different measurements. None establishes the number of missing engine functions or the percentage of the campaign that works. [Author’s statement](https://www.reddit.com/r/Ultima/comments/1vjpd5s/incremental_release_ultima_vii_revisited_025/) · [Conversion commit](https://github.com/ViridianGames/U7Revisited/commit/9484f073c3b47e83aec589b605f7700312f88074) · [Inspected tree](https://api.github.com/repos/ViridianGames/U7Revisited/git/trees/1c55579828a0e1c1c18902dac2aee412b15f3cf8?recursive=1) · [Historical inventory](https://github.com/ViridianGames/U7Revisited/blob/1c55579828a0e1c1c18902dac2aee412b15f3cf8/SCRIPTS.md)

There is direct evidence that copying those Lua files would leave the campaign broken. In the inspected Revisited revision, the registered endgame handler returns without playing the finale, the timer getter returns zero, the timer setter does nothing, and the barge lookup returns nil. Its script test defaults to syntax checking; even when execution is requested, it can fall back to syntax if data is missing. These are four useful acceptance tests for our implementation. Revisited’s Finnigan script also demonstrates why filenames are unsafe dispatch keys: its filename contains decimal NPC number 12, while the script identifies original function `040C`. [Host implementations](https://github.com/ViridianGames/U7Revisited/blob/1c55579828a0e1c1c18902dac2aee412b15f3cf8/Source/U7LuaFuncs.cpp#L5811-L5868) · [Test modes](https://github.com/ViridianGames/U7Revisited/blob/1c55579828a0e1c1c18902dac2aee412b15f3cf8/Tests/ScriptTests.cpp#L137-L193) · [Finnigan script](https://github.com/ViridianGames/U7Revisited/blob/1c55579828a0e1c1c18902dac2aee412b15f3cf8/Redist/Data/Scripts/npc_finnigan_0012.lua#L1-L8)

**Start the compiler investigation with Kitrinx’s `ultima7-usecode` tools and Exult’s `ucxt`.** Kitrinx publishes tools to inspect control flow, verify the corpus, disassemble functions, decompile the player’s `STATIC/USECODE` into a source project, and regenerate records. Exult provides a separately useful disassembler and a working interpreter. Neither tool is, by itself, our Lua backend. Qualify the existing readers before writing a new one. [Kitrinx Usecode tools](https://github.com/Kitrinx/Ultima7_Decomp/blob/872a613c718abf3a40cf94533887171bec8cfb24/ultima7-usecode/README.md) · [Exult `ucxt` manual](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/tools/ucxt/Docs/README)

One prerequisite can otherwise invalidate the whole project: **identify the actual source edition before qualifying anything.** GOG’s Complete Edition lists *Black Gate + Forge of Virtue*. Exult distinguishes expanded and unexpanded installations. Kitrinx’s conditional retail test configuration also names the expanded edition. An installation folder called `ULTIMA7`, a successful Exult `--bg` launch, or a passing upstream build does not establish that we tested vanilla Black Gate. If the only supplied copy is expanded, identify it correctly, run applicable tooling experiments, and report that vanilla campaign qualification is blocked. Do not remove a few expansion assets and call the result the base game. [GOG edition contents](https://www.gog.com/en/game/ultima_7_complete) · [Exult edition handling](https://exult.info/docs.html) · [Kitrinx corpus configuration](https://github.com/Kitrinx/Ultima7_Decomp/blob/872a613c718abf3a40cf94533887171bec8cfb24/ultima7-usecode/CMakeLists.txt)

The planning workspace contained an empty Git repository and no supplied game corpus. The findings above come from upstream inspection. **No retail conversion, local replay or campaign parity has yet been demonstrated.** Build software that makes those claims testable.

## 2. Define what “fully automated” means for the player

After supplying two supported installation paths and an output directory, the player must be able to build, verify and launch the local game without editing a map, assigning scripts, choosing art for individual objects, opening an asset editor, configuring a public shard, or asking an AI to finish the conversion. After dependencies are provisioned, conversion and gameplay must work offline.

Provide one front door, with separately runnable stages for diagnosis. The following is the **interface to implement**, not a claim that these commands exist:

```text
u7uo inspect --u7 "<Black Gate>" --uo "<UO Classic data>"
u7uo build   --u7 "<Black Gate>" --uo "<UO Classic data>" --out "<private campaign>"
u7uo verify  --campaign "<private campaign>"
u7uo play    --campaign "<private campaign>"
u7uo explain --campaign "<private campaign>" --id "<object, function, asset or diagnostic>"
```

`inspect` identifies editions, languages, file variants, effective resources, engine versions and missing inputs. `build` creates the staged client data, initial world, compiled scripts, server configuration, local client profile, manifest and exception report. `verify` distinguishes structural checks, actual engine readback and gameplay replays. `play` starts the private server, waits for readiness, launches the client and gives a useful diagnosis if either fails. `explain` traces a visible object or failed script back to its source record, mapping rule and test evidence.

Treat both installations as read-only. Build into a staging directory, verify before switching the active build, and keep saves outside generated assets. A failed build must leave the last working campaign and saves usable. Rebuilding the same locked inputs must produce identical content hashes and stable IDs; timestamps and machine-specific diagnostic paths belong outside that comparison. The local server binds to loopback, and its client profile connects there. Own only the processes started by this launcher. ModernUO exposes data-directory and listener configuration; set them explicitly instead of relying on its interactive first-run defaults. [ModernUO configuration](https://modernuo.com/docs/getting-started/configuration/)

**The developer may curate reusable conversion rules; the player must never have to repair a town or quest.** Store rules and justified exceptions in version control. Generated output is disposable. An unattended build may fail with a precise unsupported-edition or unsupported-feature report. It must never succeed by silently deleting objects, substituting quest state, or accepting an unimplemented operation.

## 3. Establish authorities before resolving discrepancies

| Question | Primary evidence | Cross-check and limit |
|---|---|---|
| What data did this edition ship? | Player-supplied files, hashes, record offsets and decoded fields | Compare Exult and a second reader. Two readers sharing code are one line of evidence. |
| What did vanilla Black Gate do? | Repeatable observation of the matching original DOS game, with the initial state and player actions recorded | Use Exult for broader instrumented runs. Record disagreements; distinguish original quirks from deliberate Exult changes. |
| What does a Usecode instruction or intrinsic mean? | Original function bytes, an applicable implementation, and a test that distinguishes competing interpretations | Use Exult, Kitrinx and Revisited for different questions. A disassembly establishes an instruction’s presence; it does not establish the result of executing it. |
| Can the generated world be used by UO? | The pinned ModernUO server and actual ClassicUO client loading the staged data, followed by real movement and interaction | Use [UOFiddler](https://uofiddler.polserver.com/) for additional inspection. A map preview cannot certify server collision. |
| Can another tool decode this asset? | A second reader with known provenance | [TITAN](https://github.com/theGreyWanderer-uc/tgwUltima/blob/d37e8a2e336dd877837497c2e4b0d68e70ae3b79/titan-ultima/README.md#capabilities) is a candidate for U7 terrain, objects, containers, eggs, schedules, sprite origins and selected UO assets. Test the relevant operation rather than assuming broad format support proves correctness. |

Maintain a small evidence ledger: claim, edition, input hash, tool or executable revision, source location or capture ID, expected result, observation, discrepancy and resolution. An explicit example of shared ancestry is Revisited’s IREG reader, which credits Exult’s implementation. An explicit example of behavioral disagreement is Exult’s documented handling of some original Black Gate music state. Do not resolve either kind of question by majority vote. [Revisited IREG reader](https://github.com/ViridianGames/U7Revisited/blob/1c55579828a0e1c1c18902dac2aee412b15f3cf8/Source/LoadingState.cpp#L1043-L1053) · [Exult intrinsic reference](https://exult.info/seventowers/exult_intrinsics.html)

**Use REA where an artifact can answer a question that source inspection has left open.** The planning session checked the connected REA server: version 6.7.0, Ghidra available as a candidate, managed assembly inspection available, and no active target. Its native UI scenario and process scenario capture routes reported unsupported on this Windows host. Re-probe in the implementation environment. Do not promise that REA can drive the DOS game, interpret U7 Usecode, or capture a Windows playthrough simply because a tool name appears in the catalog. [REA project](https://github.com/morluto/rea)

For an unresolved original behavior, write the question first: for example, *which of two otherwise identical nearby objects is returned first?* Identify the exact local executable, hash and edition. Inspect the smallest relevant routine or table when the artifact format and provider support it. Then run the distinguishing scenario in the original game or a pinned emulator. For Exult, ModernUO and ClassicUO, read source first; inspect a shipped executable or managed assembly when the question is about that build. Use local UI observation or a test build with narrow instrumentation if REA cannot make the observation. Keep static inference, runtime observation and untested hypotheses separate. Kitrinx’s reconstructed, portable and modified engines also have different evidentiary value; confirm the matched binary before treating reconstructed logic as evidence for vanilla. [Kitrinx project distinctions](https://github.com/Kitrinx/Ultima7_Decomp/blob/872a613c718abf3a40cf94533887171bec8cfb24/README.md)

Use native Codex shell, existing connectors and subagents for research and implementation. The session exposed those capabilities, and the current [Codex subagent documentation](https://developers.openai.com/codex/subagents) and [official changelog](https://learn.chatgpt.com/docs/changelog) were checked. They provide execution and delegation; they do not define a Black Gate object, freeze an edition, reproduce a scenario, or determine whether a quest passed. **The durable infrastructure justified here is the conversion CLI, the campaign compatibility layer and the replay verifier.** Keep oracle executors replaceable. Do not build an agent launcher, require WSL for context isolation, or make REA, an MCP server, or a model subscription a player dependency.

## 4. Compile the world into a source-faithful intermediate representation

Keep three things separate: **what U7 shipped**, **what the campaign simulation means**, and **how UO presents it**. A UO art ID is not a U7 shape ID. A ModernUO serial is not a persistent source identity. A screen coordinate is neither game’s world coordinate.

1. **Inventory the original data.** Discover `U7MAP`, `U7CHUNKS`, fixed object records, initial movable objects, NPCs, inventories, schedules, shape and frame metadata, type flags, palettes, portraits, fonts, text, audio and `STATIC/USECODE`. Enumerate each file and record family actually present. New games must take their mutable seed from the edition’s initial-game archive, not from the player’s last `GAMEDAT` directory. In particular, a saved `usecode.dat` is not the campaign bytecode. [Exult new-game initialization](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/gamewin.cc#L1357-L1374) · [Exult data paths](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/fnames.h#L76-L99)
2. **Preserve source identity.** For a placed object retain edition, record provenance, shape, frame, quality, flags, source position and lift, footprint, containment and order, NPC or script binding, and relevant links. For records without a durable native ID, derive a stable identity from the frozen source placement or record path. Two identical cups on the same tile are two objects. Runtime-created objects get a separate persistent identity. Never key a mutable identity by its current coordinates.
3. **Expand the original grid exactly once.** The documented Black Gate world comprises 12×12 superchunks, each containing 16×16 chunks of 16×16 tiles: **3,072×3,072 logical tiles**. Preserve U7 axes and adjacency. Embed the source rectangle in the target facet with one documented transform and its inverse. Do **not** rotate the map data 45 degrees: ClassicUO already projects logical coordinates onto the screen. Translate lifts to target Z using measured floor, stair, roof and reachability fixtures. Do not infer height from sprite pixels. [Exult Studio world terminology](https://exult.info/studio.html) · [ClassicUO projection](https://github.com/ClassicUO/ClassicUO/blob/ee79d7ebc1cc0e53ff84fe6cae17d389e2737f93/src/ClassicUO.Client/Game/GameObjects/GameObject.cs)
4. **Represent topology as well as geography.** Preserve stacked floors, concealed rooms, teleporter destinations, dungeons, doors, bridges, ships and barges, including positions that look like empty or inaccessible land on a surface map. Implement original wrap behavior for relevant movement, sailing, proximity searches and path destinations. Padding outside the U7 rectangle must never become a shortcut or searchable campaign territory. [Exult wrapped coordinates](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/tiles.h#L58-L69)
5. **Classify by behavior, not source filename.** Emit ground as land tiles; immutable scenery as target statics; manipulable, searchable, mutable or quest-relevant objects as persistent entities, or through an equivalent queryable representation with identical behavior. Emit NPCs, containers, vehicles, eggs and triggers with their own semantics. Where dynamic lookup prevents proof that something is decorative, preserve its identity. A quest item must not disappear under shard item decay, and a door must not exist twice as both blocking static art and an interactive item.

Publish reconciliation counts. Every decoded source occurrence must lead to an emitted representation, membership in a documented composite, or a specific diagnostic. Verify ownership and containment graphs, references, coordinate bounds and record consumption. Unknown bytes remain identifiable by source range; malformed or unrecognized records must not shift parsing of the rest of a region.

## 5. Make the result look and function like Ultima Online

Use the player’s **installed UO artwork first**. Build a catalog from the selected target data: land tiles, item art, bodies, animations, equipment layers, Gumps, sounds and applicable metadata. Resolve target IDs against that catalog instead of assuming IDs from another client era are available.

Map source **families and states**: open and closed doors, occupied and empty beds, lit and unlit lamps, wall ends and corners, single and stacked items, NPC bodies and worn equipment. A mapping rule specifies the eligible source shapes or frames, contextual constraints, target pieces, anchor, collision, visible state and interaction component. Reject candidates with the wrong footprint, orientation, walkability or state transitions before ranking them by appearance. Image similarity may propose a mapping for developer review; it cannot approve one.

For buildings, generate walls, floors, corners, openings, roof groups and stairs from structural rules. Verify that the player can walk through an open doorway, cannot walk through a closed wall, can reach the next floor, can see and select a relevant object under a roof, and can return along the same route. For a uniquely shaped quest prop, preserving recognizable identity matters more than finding a superficially similar UO decoration.

Where there is no acceptable UO equivalent, use an explicit, repeatable local conversion or reviewed custom-art recipe. Decode U7 palettes, transparency, frame origins and animation timing before rendering. Preserve portrait crops and readable book or sign text. Track the target’s art slots, dimensions, offsets, animation directions, hue behavior and tile flags. A single U7 sprite does not contain every occluded surface or every UO walking direction; record exactly which views came from source, a reusable construction rule or authored art. Do not promise automatic reconstruction of missing views. Keep placeholders visible in development builds and out of qualified releases.

Inventory music, ambient triggers, sound effects, speech, intros and endings separately. For each, declare whether the local build uses an original locally converted asset, an equivalent UO cue, or a purpose-built presentation. Preserve script-visible timing, choices, cues and outcomes. Disabling sound must not deadlock a conversation or skip a required event. A completion flag without the corresponding ending presentation is incomplete.

**Pin one UO data profile and reuse a supported visible facet slot in a private installation.** Start with slot 0; retain the dimensions recognized by the selected client and server and pad outside the campaign deterministically. Record server map index, client-visible ID, file index, dimensions, season, map rules, and client version. Disable stock starts, spawns and regions that would intrude. Do not hardcode the often-repeated 6,144-tile width: the inspected ModernUO stock profile defines slot 0 as **7,168×4,096**. The source campaign is smaller than either; the real requirement is that both target engines agree. [ModernUO map definitions](https://github.com/modernuo/ModernUO/blob/1c63a13b23ef53cab18032d19d870d13b2a85f4a/Distribution/Data/map-definitions.json)

For the first writer, emit the staged map, statics and static index in the supported MUL layout. Verify block ordering, 8×8 local coordinates, elevations, empty blocks, offsets, lengths and per-block limits using asymmetric fixtures. Control competing UOPs, DIFs and alternate files in **the private staging area only**. This is a real failure mode: the inspected ModernUO loader tries `mapN.mul` first; ClassicUO can prefer `mapNLegacyMUL.uop` in a recognized UOP installation. A player can otherwise **see stock terrain while colliding with the converted terrain**. The inspected ClassicUO reader also caps ordinary statics at 1,024 per block. Fail on overflow instead of accepting invisible objects. Read landmarks back through both actual loaders, including at the first and last campaign blocks. [ModernUO file selection](https://github.com/modernuo/ModernUO/blob/1c63a13b23ef53cab18032d19d870d13b2a85f4a/Projects/Server/TileMatrix/TileMatrix.cs#L105-L125) · [ClassicUO file selection](https://github.com/ClassicUO/ClassicUO/blob/ee79d7ebc1cc0e53ff84fe6cae17d389e2737f93/src/ClassicUO.Assets/MapLoader.cs#L145-L191) · [ClassicUO static limit](https://github.com/ClassicUO/ClassicUO/blob/ee79d7ebc1cc0e53ff84fe6cae17d389e2737f93/src/ClassicUO.Assets/MapLoader.cs#L360-L368)

## 6. Translate Usecode to Lua without translating away its meaning

Use this production path:

```text
Owner’s STATIC/USECODE
  → decoded function records and instructions
  → validated control flow with original IDs and byte offsets
  → generated Lua plus source maps
  → versioned Black Gate host operations
  → authoritative campaign state in ModernUO
```

**The original bytecode is the input. Revisited’s Lua is comparison material.** If a distributable Revisited translator is subsequently found, put it through the same qualification and reuse it if it passes. A collection of hand-edited translations is not a build dependency. Do not use an LLM to rewrite each function during installation.

- **Qualify the front end.** Run Kitrinx’s structural verifier and compare decoded functions with Exult `ucxt`. On the exact vanilla corpus, run `u7ucround --generate --detail` and capture exit status, total functions, identical regenerations, refusals, size differences and byte differences. Its optional writer can copy back an original record when regeneration fails; a matching rebuilt file hash alone can therefore hide a failure. Detect skipped retail tests. For records that fail structural recovery, retain the original instructions and use a verified basic-block emitter rather than guessing source text. Track which path produced every function. [Round-trip implementation](https://github.com/Kitrinx/Ultima7_Decomp/blob/872a613c718abf3a40cf94533887171bec8cfb24/ultima7-usecode/tools/u7ucround.c#L88-L139)
- **Handle control flow mechanically.** Recover function records, operands, strings, externals, branch targets, calls, stack effects and event/object context. Emit readable structured Lua where verified. For valid but awkward jumps, emit labeled basic blocks through an explicit program counter. Preserve order of evaluation, side effects and return behavior. Every generated failure must identify the edition, original function ID, original instruction offset, event, object and Lua location. Do not introduce a second production VM merely to hide a transpiler defect.
- **Define a Usecode value model.** Implement measured rules for integer widths and signedness, arithmetic, equality, truth tests, strings, arrays, object references, special references and invalid values. Do not inherit Lua defaults by accident. Examples: Exult treats integer zero and an empty array as false; Lua treats zero and tables as true. Exult’s documented implementation of an out-of-range array read can yield zero, not Lua `nil`. Test these before trusting even a simple dialogue branch. [Usecode truth conversion](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/usecode/useval.h#L396-L410) · [Array indexing](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/usecode/ucinternal.cc#L2248-L2304)
- **Separate four inventories.** Count bytecode opcodes, calls between Usecode functions, calls to game-engine intrinsics, and commands inside immediate or delayed action arrays. A name such as `unknown_XXXXH` is not enough to classify a call. Resolve numeric identities in the correct edition. Report distinct operations, static call sites and observed runtime invocations separately. The secondary action-script language needs its own decoder, scheduler and tests. [Black Gate intrinsic dispatch](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/usecode/bgintrinsics.h#L23-L30) · [Exult scheduled scripts](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/usecode/ucsched.cc#L754-L821)
- **Give each intrinsic a testable contract.** Record numeric ID, arguments, coercions, return value, side effects, ordering, failure behavior, source evidence and test status. Prioritize by campaign reachability and consequence as well as frequency: the endgame may run once and still block release. Unknown reachable operations produce a diagnostic and a failed scenario. Never substitute a plausible zero, empty list, or successful no-op.
- **Use a narrow Lua host.** Start with a pinned managed Lua runtime such as [MoonSharp](https://www.moonsharp.org/) and emit a conservative Lua subset. Keep game strings and binary source data distinct; MoonSharp documents Unicode strings and source-level compatibility. Expose explicit game operations and opaque handles, not arbitrary .NET objects, filesystem access or network access. Keep deterministic clock, randomness and instruction budgets in the host. Prove the selected runtime on a real conversation, delayed action and save/resume before committing to it for the full corpus. [Runtime differences](https://www.moonsharp.org/moonluadifferences.html) · [Host API controls](https://www.moonsharp.org/sandbox.html)

Implement the compatibility behavior once per operation, then let the original functions compose it. Prefer one correct “find nearby object” implementation over twenty quest-specific patches. For example, validate which identical object a search returns, how an item inside a container obtains its world position, and when a search depends on the visible region. The result must not change because the player resized the ClassicUO window or the server enumerated objects in a different order. [Exult search ordering](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/usecode/ucinternal.cc#L996-L1015) · [Viewport-sensitive search](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/usecode/intrinsics.cc#L851-L878)

## 7. Run a Black Gate campaign inside ModernUO

ModernUO owns persistent campaign state. ClassicUO presents it and supplies player actions. Build a server module linking original identities to UO items and mobiles, and route double-click, use-on-target, movement, proximity, conversation, combat, death, inventory changes and scheduled callbacks into the right original event context. Support world objects created, moved, transformed or destroyed after the initial import. A save/reload must neither resurrect a removed item nor duplicate a spawned one.

Implement the behaviors the scripts depend on: party membership and equipment; NPC identity, schedules, activity and pathfinding; calendar, time and timers; quantities, qualities, ownership, keys, doors and containers; eggs, probability and activation conditions; dialogue answers and global flags; shops, books and signs; spells and quest artifacts; boats, moving platforms and teleporters. Preserve success and failure callbacks. When a party member is blocked from a destination, establish whether the original script waits, retries, fails or continues. A UO pathfinder returning “no route” is not a sufficient implementation of that contract.

**Conversations use ordinary UO Gumps.** Double-clicking an NPC starts the corresponding original event. The server displays the actual speaker, original locally decoded text, portrait where applicable, and currently available topics. A button response resumes the suspended function. Support topic addition/removal, repeated topics, party interjections, text or number prompts, cancellation, and world mutations between lines. Use original object and event IDs for dispatch. Bind replies to the current conversation and accept a choice once. An old or duplicated reply must not award an item twice. Derive pause behavior from the reference scenario; keep the UI responsive while simulated time is paused. Start with an unmodified ClassicUO client and locally generated portrait resources. [ModernUO Gump and reply support](https://modernuo.com/packets.html)

**Save the logical continuation, not a live Lua coroutine or a ModernUO timer token.** Store the current function and resume point, necessary locals/stack, conversation state, object references, pending action sequences, logical due times and ordering, campaign clock, RNG state and world changes. Snapshot them consistently. On restart restore identities before resuming work, rebind timers exactly once, and reconnect the Gump to the correct session. Persist build/profile identity with saves; reject incompatible saves with an explanation unless a tested migration exists. [ModernUO serialization](https://modernuo.com/docs/development/serialization/) · [ModernUO timers](https://modernuo.com/docs/development/timers/)

Keep ordinary UO combat where it preserves the campaign. Where original scripts inspect death, unconsciousness, possession, equipment, party status, spell effects or the survival of a particular character, implement the original observable result. Test a case where default shard rules would give a different result. Do not compensate by setting a quest flag behind the player’s back.

## 8. Prove the conversion in this order

| Gate | Deliverable | Acceptance condition |
|---|---|---|
| **0. Inputs and synthetic fixtures** | Edition inspector, tool locks, synthetic U7/UO records, initial report | Clean machine distinguishes missing, vanilla, expanded, mixed and unknown inputs. Synthetic CI runs without commercial assets. A skipped retail check is visibly **not run**. |
| **1. Compiler and target proof** | One generated terrain block, one fixed object, one nested container, one NPC, one portrait and one translated function | Both real UO loaders read the same asymmetric landmark and elevation; the player can reach and interact with it; the Lua branch produces the reference state change. |
| **2. Trinsic** | Original opening and town investigation on the converted facet | Start a normal new game, converse with Iolo and Finnigan, investigate the stables, obtain the source-defined progression needed to leave town, and leave through ordinary play. Verify topics, inventory, flags, gate behavior and continuity after restart. No GM commands, injected quest flags, prerecorded dialogue tree, or manually placed substitute quest objects. |
| **3. Whole-world conversion** | All source regions compiled; geometry, identity, media and script coverage reports | Every source region and record is reconciled. Check representative towns, wilderness, islands, interiors, dungeons and seams. Validate roofs, stairs, doors, vehicles, hidden destinations, schedules, density limits and agent reachability. Report unsupported interactions even if the map renders. |
| **4. Campaign qualification** | Full main-route replay, alternative ending checks, and a declared inventory of side content and systemic interactions | A new character reaches the ending through normal play. Exercise both Black Gate ending outcomes from legitimate prior state. Verify the presentation, resulting state, key optional content, and save/restart at multiple points. No unresolved reachable operation may be hidden behind a passing main-route replay. [Black Gate endgame outcomes](https://exult.info/seventowers/exult_intrinsics.html) |
| **5. Player release** | Offline launcher, verified local install, backup/restore, build manifest, exception report and compatibility matrix | Repeat from clean staged output using only the declared inputs and provisioned tools. Rebuild without changing content hashes, relaunch offline, load an existing compatible save, and recover cleanly from an interrupted build. |

Build the replay verifier around **player intentions and observable results**, not pixel coordinates shared across engines. A scenario says “talk to this NPC, select this available topic, move this item, wait this many logical ticks, save, restart and inspect this state.” Each adapter translates those actions into its engine’s controls. Record ordered dialogue/topic IDs or private text hashes, object and inventory changes, flags, callback order, position, logical time and ending state. Compare screenshots for rendering, clipping and reachability; do not demand pixel equality between U7 and UO. For Exult, first run a known calibration case: its intrinsic trace hook is build-dependent. [Exult trace implementation](https://github.com/exult/exult/blob/dba00df48237c4b33862f0a9892a8001f75d6eb8/usecode/ucinternal.cc#L1545-L1558)

Include these regression cases from the beginning:

- Zero and an empty array take the observed Usecode branch. An out-of-range read produces the measured value. A script call and a same-numbered host operation cannot be confused.
- Two identical objects occupy one location; one is moved inside a container. A search returns the correct original instance before and after reload.
- A door changes frame, appearance and collision together. A staircase reaches the intended floor. An actor behind a roof remains selectable when the reference allows it.
- A timer is set, the campaign is saved, both programs exit, and the due action runs **exactly once** after restart. Repeat with a conversation suspended and a party member walking toward a callback.
- The Avatar crosses a world seam on foot or by boat as applicable. Proximity searches and destination calculations use the campaign boundary, not the edge of the padded UO facet.
- A conflicting stock map is deliberately placed in a **test staging profile**. Verification detects client/server disagreement. An overfull statics block also fails before launch.
- Removing a required input, introducing an unknown reachable intrinsic, or disabling the retail data for an execution test cannot turn a failure into a syntax-only pass.

For every gate, report raw denominators: source records inventoried/decoded/emitted; unique shape/frame families and placed occurrences covered; functions decoded/generated/executed; opcodes and intrinsics encountered/implemented/tested; static call sites versus observed calls; scenarios passed/failed/not run. Separate exact semantic matches, deliberate UO presentation substitutions, unresolved behavior and evidence gaps. A 99% asset count cannot outweigh one missing endgame operation.

## 9. Deliver the evidence with the software

Ship the converter, authored mapping rules, synthetic fixtures, source maps, versioned runtime interfaces, data-free installation guide, profile manifests and a readable compatibility report. Keep commercial assets, generated maps and dialogue, retail-derived Lua, saves, disassemblies and content-bearing captures private to the player’s machine by default. Review the provenance of anything proposed for distribution; repository-level licensing is not a substitute for checking individual material. Kitrinx, for example, expressly distinguishes newly authored code from pre-existing material. [Kitrinx license](https://github.com/Kitrinx/Ultima7_Decomp/blob/872a613c718abf3a40cf94533887171bec8cfb24/LICENSE)

After the Trinsic gate, give an estimate for the remaining campaign based on measured work: unresolved intrinsic families, source functions requiring fallback, architectural exceptions per building, unmapped art families, failed scenario classes, and the cost of a verified fix. Also publish cold build time, warm rebuild time, output size, startup time, peak memory and worst observed gameplay stalls on a named machine. Do not extrapolate campaign completion from how quickly terrain was generated.

**The first demonstration should be small enough to audit and hard enough to matter:** launch ClassicUO locally, walk through converted Trinsic, speak to Finnigan through a Gump generated from the player’s own Usecode, make a choice that changes the world, save, restart, and show that the same NPC, item, conversation state and gate condition still agree with the reference. That one sequence tests the world compiler, the Lua translation, the UO host, the client assets and persistence together. Build outward from that evidence until a player can finish vanilla Black Gate.
